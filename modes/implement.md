## 判定原則

- 差分は最小にする。依頼目的に直結しない整理・リネーム・抽象化を混ぜない
- 既存コードの書き方（命名、構成、コメントの量）に揃える
- 冗長なコードコメントは避け最小にする。何をしているか(What)ではなく、なぜそうしているか(Why)、処理の流れを(Overview)を伝える

## 停止条件

- build / test / lint が exit 0。判定はコマンドの実行結果で行い、自己申告は認めない

## Gate

- PR 作成、マージ
- 仕様変更を伴う逸脱の承認
